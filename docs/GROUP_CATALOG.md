# 초대 기반 그룹 지도

## 적용된 정책

- 로그인한 회원은 모두 까탈리스트이며 그룹 생성과 초대가 가능하다.
- 그룹 생성자는 추가 관리 권한을 갖지 않는다. `created_by`는 기록용 필드다.
- 초대 링크로 로그인하면 승인 절차 없이 해당 그룹에 참여한다.
- 계정 패널의 그룹 체크박스로 지도에 표시할 그룹을 선택한다.
- 음식점·메뉴·사진은 가입한 그룹에서만 조회한다.
- 등록자는 자신의 음식점 정보·메뉴·사진을 수정하고 삭제한다.
- 최초 메달은 수정 화면과 직접 API 요청으로 변경할 수 없다.
- 그룹원은 댓글을 작성하고 자신의 댓글만 수정·삭제한다.
- 음식점 등록자를 제외한 전체 그룹원이 상승·유지·하락에 투표한다. 한 사람당 한 표이며 결과 확정 전까지 선택을 바꿀 수 있다.
- 등록자를 제외한 현재 그룹원 과반수가 상승·하락에 동의하면 메달을 한 단계 변경하고 표를 초기화해 새 투표를 시작한다. 유지는 메달과 투표 라운드를 그대로 둔다.
- 금메달에서는 상승할 수 없다. 동메달에서 하락이 확정되면 해당 그룹의 음식점·사진·댓글·투표를 삭제한다. 다른 그룹의 같은 장소는 유지한다.
- 관리자 모드, 건의 심사, 방문 인증, 3곳 방문 승급의 앱 접근은 종료했다.

## 저장 구조와 접근 제어

`catalog_groups`와 `catalog_group_members`가 그룹과 소속을 관리한다.
음식점은 `group_id`, `created_by`를 가지며 RLS가 소속과 작성자를 검증한다.
그룹 생성·초대 발급·가입은 인증 검사와 트랜잭션을 갖춘 함수로 수행한다.
초대는 192비트 임의 토큰이며 DB에는 해시만 저장한다. 새 링크 발급 시 확인창을 표시하고 기존 링크를 폐기한다.
로그인 이동 전 초대 토큰을 sessionStorage에 보관하고 가입 후 지운다.

사진 버킷은 비공개다. 그룹원만 180초 유효한 서명 URL을 발급하며 앱은 120초 간격으로 갱신한다.
발급된 URL은 만료까지 유효하고 이미 내려받은 파일은 회수할 수 없다.
과거 공개 사진 URL의 브라우저 캐시나 저장된 사본도 회수 대상에 포함되지 않는다.

같은 이름(공백 제거, 소문자)과 소수점 5자리 좌표를 같은 장소로 판단한다.
한 그룹 안의 중복 등록은 차단하며 여러 그룹에서는 독립적인 기록을 유지한다.
지도에서는 해당 장소의 핀을 묶고 상세창에서 그룹별 기록을 선택한다.
외부 장소 고유 ID가 제공되지 않아 명칭·좌표가 다른 검색 결과는 자동 병합하지 않는다.

## 댓글과 투표

`restaurant_comments`는 그룹원 전용 RLS와 작성자 전용 수정·삭제 정책을 가진다.
본문은 최대 1,000자이며 최신순으로 20개씩 읽는다. 작성자 닉네임은 해당 그룹 음식점의 댓글 조회에서만 제공한다.
의견 창이 열린 동안 15초 간격으로 갱신하며, 이전 의견을 펼친 경우 새로고침으로 목록을 다시 읽는다.

`restaurant_votes`는 직접 쓰기를 허용하지 않는다. `cast_restaurant_vote`는 그룹과 음식점 순서로 잠금을 잡고 등록자 제외, 그룹 소속, 투표 라운드와 과반수를 검사한다.
동일 라운드의 사용자 표를 교체하며, 메달 변경 후 지연 도착한 이전 라운드 요청은 거절한다.
그룹 가입과 탈퇴도 같은 그룹 잠금을 사용한다. 과반수는 투표 요청을 처리하는 시점의 인원을 기준으로 계산한다.

음식점 삭제는 댓글·투표·사진 메타데이터를 함께 삭제한다. 파일 경로를 내부 삭제 대기열에 일시적으로 넣고 Storage API로 실제 파일을 삭제한 뒤 작업 항목도 지운다.
삭제 트랜잭션에서 즉시 서버 작업을 요청하고, 네트워크 실패 시 매분 실행하는 Cron이 재시도한다.
`catalog-photo-cleanup`은 192비트 작업별 토큰으로 인증하고 서버 환경의 서비스 키만 사용한다. 프론트엔드에는 작업 토큰과 서비스 키를 전달하지 않는다.
그룹원의 사진 업로드와 음식점 삭제는 행 잠금으로 순서를 보장해 파일 누락을 방지한다.

## 기존 데이터 이전

이전 시 관리자 계정이 정확히 하나인지 확인하고 해당 계정의 `까탈로그` 그룹을 생성했다.
사용자가 승인한 동일한 ‘백운동’ 중복 기록 한 건을 통합해 음식점 21곳과 사진 4장을 보존했다.
기존 방문·건의·관리자 테이블은 이력 보존용으로 두고 클라이언트 권한과 기존 RPC 실행 권한을 회수했다.

## 검증

- `npm test`: 데이터 정규화, 장소 병합, 배포 CSS 블러 선언 검사
- `npm run test:e2e`: PC Chromium·모바일 WebKit의 그룹/초대/작성자 편집/사진/독·검색 검사
- `npm run build`와 `npm run test:glass`: 압축 CSS의 블러 회귀 검사
- `tests/group-access.sql`: 실제 DB에서 테스트 사용자·그룹을 만들고 RLS, 타 그룹 차단, 사진 권한, 중복 등록 및 메달 변경 차단을 검사한 뒤 롤백
- `tests/discussions-and-votes.sql`: 등록자 제외, 과반수, 표 교체, 라운드 초기화, 댓글 작성자 권한, 동메달 삭제와 다른 그룹 보존을 검사한 뒤 롤백
- `tests/photo-cleanup.test.js`: 파일 목록 페이지 처리, 경로 범위, 일시적 삭제 실패와 재시도 검사
- `tools/verify-live.mjs`: 로그인하지 않은 실제 배포 화면과 지도·위치·블러 확인

DB 보안 점검에서 종료한 테이블과 내부 초대 테이블의 ‘RLS 정책 없음’ 안내는 의도한 접근 차단이다.
기존 [유출 비밀번호 보호 미설정 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 남아 있으며, 이번 카카오 로그인·그룹 권한 변경에서 비밀번호 인증 설정은 변경하지 않았다.
