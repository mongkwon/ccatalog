# 초대 기반 그룹 지도

## 적용된 정책

- 로그인한 회원은 모두 까탈리스트이며 그룹 생성과 초대가 가능하다.
- 그룹 생성자는 추가 관리 권한을 갖지 않는다. `created_by`는 기록용 필드다.
- 초대 링크로 로그인하면 승인 절차 없이 해당 그룹에 참여한다.
- 계정 패널의 그룹 체크박스로 지도에 표시할 그룹을 선택한다.
- 음식점·메뉴·사진은 가입한 그룹에서만 조회한다.
- 등록자는 자신의 음식점 정보·메뉴·사진을 수정하고 삭제한다.
- 등록자는 수정 화면에서 메달을 변경할 수 있다. 실제로 메달이 바뀔 때 기존 상승·유지·하락 표를 모두 초기화한다. 같은 메달로 저장하거나 다른 정보만 수정하면 표를 유지한다.
- 그룹원은 댓글을 작성하고 자신의 댓글만 수정·삭제한다.
- 음식점 등록자를 제외한 그룹원이 상승·유지·하락 의견을 선택한다. 한 사람당 한 표이며 선택을 바꿀 수 있다.
- 의견은 항목별 표 수만 보여준다. 메달을 자동 변경하거나 음식점을 자동 삭제하지 않는다. 금메달에서도 상승 의견을 남길 수 있다.
- 사진은 음식점 추가·수정 창에서 추가·삭제·순서를 편집한 뒤 저장한다. 상세창은 사진 크게 보기만 제공한다.
- 상단은 로고·플러스·프로필 순서이며 하단 독은 유지한다.
- 관리자 모드, 건의 심사, 방문 인증, 3곳 방문 승급의 앱 접근은 종료했다.

## 저장 구조와 접근 제어

`catalog_groups`와 `catalog_group_members`가 그룹과 소속을 관리한다.
음식점은 `group_id`, `created_by`를 가지며 RLS가 소속과 작성자를 검증한다.
그룹 생성·초대 발급·가입은 인증 검사와 트랜잭션을 갖춘 함수로 수행한다.
초대는 192비트 임의 토큰이며 DB에는 해시만 저장한다. 새 링크 발급 시 확인창을 표시하고 기존 링크를 폐기한다.
로그인 이동 전 초대 토큰을 sessionStorage에 보관하고 가입 후 지운다.

사진 버킷은 비공개다. 그룹원만 180초 유효한 서명 URL을 발급하며 앱은 120초 간격으로 갱신한다.
발급된 URL은 만료까지 유효하고 이미 내려받은 파일은 회수할 수 없다.
과거 공개 사진 URL의 브라우저 캐시나 저장된 사본도 회수 대상에 포함되지 않는다.

같은 이름(공백 제거, 소문자)과 소수점 5자리 좌표를 같은 장소로 판단한다.
한 그룹 안의 중복 등록은 차단하며 여러 그룹에서는 독립적인 기록을 유지한다.
지도에서는 해당 장소의 핀을 묶고 상세창에서 그룹별 기록을 선택한다.
외부 장소 고유 ID가 제공되지 않아 명칭·좌표가 다른 검색 결과는 자동 병합하지 않는다.

## 댓글과 투표

`restaurant_comments`는 그룹원 전용 RLS와 작성자 전용 수정·삭제 정책을 가진다.
본문은 최대 1,000자이며 최신순으로 20개씩 읽는다. 작성자 닉네임은 해당 그룹 음식점의 댓글 조회에서만 제공한다.
의견 창이 열린 동안 15초 간격으로 갱신하며, 이전 의견을 펼친 경우 새로고침으로 목록을 다시 읽는다.

`restaurant_votes`는 직접 쓰기를 허용하지 않는다. `cast_restaurant_vote`는 음식점 잠금을 잡고 등록자 제외, 그룹 소속과 메달 버전을 검사한다.
사용자 표를 교체하며, 작성자가 메달을 변경한 후 지연 도착한 이전 버전 요청은 거절한다.
메달 수정은 기존 작성자 전용 RLS를 따른다. DB 트리거가 메달 변경과 표 삭제·버전 증가를 같은 트랜잭션에서 처리한다.

음식점 삭제는 댓글·투표·사진 메타데이터를 함께 삭제한다. 파일 경로를 내부 삭제 대기열에 일시적으로 넣고 Storage API로 실제 파일을 삭제한 뒤 작업 항목도 지운다.
삭제 트랜잭션에서 즉시 서버 작업을 요청하고, 네트워크 실패 시 매분 실행하는 Cron이 재시도한다.
`catalog-photo-cleanup`은 192비트 작업별 토큰으로 인증하고 서버 환경의 서비스 키만 사용한다. 프론트엔드에는 작업 토큰과 서비스 키를 전달하지 않는다.
그룹원의 사진 업로드와 음식점 삭제는 행 잠금으로 순서를 보장해 파일 누락을 방지한다.

## 그룹 탈퇴

계정 패널의 그룹별 탈퇴 버튼으로 나간다. 해당 그룹에서 본인이 등록한 음식점과 관련 사진·댓글·표를 삭제하며, 다른 음식점에 남긴 본인의 댓글·표도 삭제한다. 다른 그룹의 기록은 유지한다.
마지막 그룹원이 탈퇴하면 그룹과 초대 링크도 삭제한다. 별도의 그룹 삭제 기능은 제공하지 않는다. 삭제된 장소는 다시 등록할 수 있다.
음식점·댓글·표의 그룹 회원 복합 외래 키가 탈퇴 시 삭제를 보장한다. 사진 파일 정리는 기존 삭제 대기열과 서버 재시도를 재사용한다. 초대 참여·발급과 탈퇴는 그룹 행 잠금으로 순서를 보장한다.

## 화면 갱신

맛집 추가·수정의 이름 칸에는 네이버지도 공유 링크 또는 식당명·주소가 포함된 공유 문구를 붙여넣을 수 있다. `naver-place-search`가 단축 링크의 이동 경로와 공개된 장소 데이터를 확인한다. 확인된 장소 또는 공유 문구의 이름·주소가 검색 결과 한 곳과 일치하면 자동 입력하며, 불확실한 후보는 사용자가 선택한다. 네이버가 장소 조회를 제한하거나 정보가 부족하면 이름 검색으로 안내한다. 가져오기만으로 저장하지 않고 메뉴·사진 등 작성 중인 내용은 유지한다.
서버는 HTTPS의 명시된 네이버 지도 도메인만 요청하고 모든 리다이렉트를 재검사한다. API 비밀 키·쿠키는 장소 페이지 요청에 전달하지 않으며, 응답 크기·이동 횟수·시간을 제한하고 스크립트는 실행하지 않는다.

계정 패널에서 본인 닉네임(1~30자)과 참여 그룹 이름(1~40자)을 수정한다. 그룹원은 이름 열만 수정할 수 있고 닉네임은 기존 본인 전용 정책을 따른다.
이름 변경 트리거는 본인·그룹별 비공개 Realtime 채널에 내용 없는 알림을 보낸다. 수신자는 `catalog_name_context`에서 현재 가입 권한을 다시 확인한 뒤 필요한 이름만 조회한다. 프로필의 비공개 필드를 다른 회원에게 공개하지 않는다. 재연결 시 다시 조회하고, 연결이 끊기면 30초 간격으로 보완한다. 댓글 작성 중인 입력과 기존 스크롤은 유지한다.

식당 상세 주소는 `#/restaurants/<uuid>` 형식이다. 지도는 유지한 채 식당 선택을 주소·브라우저 뒤로/앞으로 가기와 동기화한다. 공유 링크의 식당은 회원 데이터 조회가 끝난 뒤 열며, 삭제·접근 불가 링크에는 동일한 안내를 표시한다. OAuth 로그인 전 식당 ID를 해당 탭에 최대 30분 보관하고 로그인 후 한 번 복원한다. 기존 로그인 Redirect URL과 초대 링크는 유지한다.

같은 계정의 정보 갱신에서는 기존 목록을 유지하고 변경된 레코드만 교체한다. 동일 좌표의 지도 핀은 위치를 다시 지정하지 않는다. 사진 서명 URL을 갱신할 때는 새 이미지를 미리 읽고 디코딩한 뒤 교체해 기존 사진을 유지한다.

## 기존 데이터 이전

이전 시 관리자 계정이 정확히 하나인지 확인하고 해당 계정의 `까탈로그` 그룹을 생성했다.
사용자가 승인한 동일한 ‘백운동’ 중복 기록 한 건을 통합해 음식점 21곳과 사진 4장을 보존했다.
기존 방문·건의·관리자 테이블은 이력 보존용으로 두고 클라이언트 권한과 기존 RPC 실행 권한을 회수했다.

## 검증

- `npm test`: 데이터 정규화, 장소 병합, 배포 CSS 블러 선언 검사
- `npm run test:e2e`: PC Chromium·모바일 WebKit의 그룹/초대/작성자 편집/사진/독·검색 검사
- `npm run build`와 `npm run test:glass`: 압축 CSS의 블러 회귀 검사
- `tests/group-access.sql`: 실제 DB에서 테스트 사용자·그룹을 만들고 RLS, 타 그룹 차단, 사진 권한, 중복 등록 및 메달 변경 차단을 검사한 뒤 롤백
- `tests/discussions-and-votes.sql`: 작성자 메달 수정, 표 교체, 메달 변경 시 초기화, 댓글 권한, 동메달 하락 의견에도 기록 보존을 검사한 뒤 롤백
- `tests/photo-cleanup.test.js`: 파일 목록 페이지 처리, 경로 범위, 일시적 삭제 실패와 재시도 검사
- `tests/group-departure.sql`: 탈퇴 연쇄 삭제, 타 그룹 보존, 마지막 그룹 자동 삭제, 재등록, 초대·접근 회수 검사 후 롤백
- `tests/reconcile.test.js`: 변경 없는 갱신의 참조 유지와 목록 변경 반영 검사
- `tests/catalog-names.sql`: 닉네임·그룹 이름 수정 권한과 길이 제한, 비공개 채널·탈퇴 후 접근 회수 검사 후 롤백
- `tests/catalog-names.test.js`: 늦게 도착한 이름 조회 결과의 덮어쓰기 방지 검사
- `tools/verify-live.mjs`: 로그인하지 않은 실제 배포 화면과 지도·위치·블러 확인

DB 보안 점검에서 종료한 테이블과 내부 초대 테이블의 ‘RLS 정책 없음’ 안내는 의도한 접근 차단이다.
기존 [유출 비밀번호 보호 미설정 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 남아 있으며, 이번 카카오 로그인·그룹 권한 변경에서 비밀번호 인증 설정은 변경하지 않았다.
