## 까탈로그

### 지인들의 취향과 추천 메뉴를 함께 기록하는 맛집 네트워크

개인 프로젝트

[서비스 바로가기](https://mongkwon.github.io/ccatalog/) · [GitHub](https://github.com/mongkwon/ccatalog)

## 1. 기획 배경

지인에게 추천받은 음식점을 지도에 저장해도, 방문할 때는 어떤 메뉴를 추천받았는지 기억나지 않는 경우가 있었다. 장소를 저장하는 행동과 추천 내용을 기록하는 행동이 분리돼 있었기 때문이다.

직접 사용한 지도 서비스의 메모·리스트 공유 방식에서도 공동 관리의 불편을 느꼈다. 리스트 소유자가 등록과 수정을 담당하는 흐름에서는 구성원들이 각자의 추천을 자유롭게 추가하고 관리하기 어려웠다.

까탈로그는 **음식점과 추천 메뉴를 함께 기록하고, 초대한 사람들과 각자의 추천을 쌓는 경험**에서 출발했다. 이름은 ‘까탈스럽다’와 기록을 뜻하는 ‘로그(log)’를 결합했다.

기존 서비스에 대한 서술은 기획자의 사용 경험을 바탕으로 한다. 특정 서비스의 최신 기능 전체에 대한 비교 조사로 제시하지 않는다.

## 2. 해결할 문제와 가설

| 문제 | 설계 방향 | 확인할 가설 |
| --- | --- | --- |
| 저장한 음식점의 추천 메뉴를 잊는다 | 장소에 메뉴·가격·사진을 함께 기록한다 | 방문할 때 대화 내용을 다시 찾는 수고를 줄일 수 있다 |
| 한 사람이 공유 목록을 관리한다 | 그룹원 모두 등록하고 자기 기록을 관리한다 | 구성원들이 추천을 지속적으로 추가하기 쉬워진다 |
| 추천자의 취향과 평가 맥락이 부족하다 | 등록자·메달·댓글·평가 의견을 제공한다 | 자신의 취향에 맞는 추천을 판단하는 데 도움이 된다 |

위 가설은 개인적인 사용 경험을 바탕으로 설정했다. 사용자 인터뷰와 실제 이용 데이터에 의한 효과 검증은 후속 과제다.

## 3. 대상 사용자와 서비스 목표

### 대상 사용자

- 친구·동료·가족과 음식점을 자주 추천하는 사람
- 추천받은 음식점의 메뉴까지 기억하고 싶은 사람
- 서로 다른 모임의 맛집을 한 지도에서 확인하고 싶은 사람

### 서비스 목표

**‘어디에 갈지’와 ‘무엇을 먹을지’를 지인들의 추천 기록에서 함께 찾을 수 있도록 한다.**

사용자는 그룹별 관계를 유지하면서 여러 그룹의 추천을 한 지도에서 탐색한다. 음식점 평가에는 등록자의 취향을 남기고, 다른 구성원이 자신의 의견을 추가할 수 있도록 한다.

## 4. 핵심 사용자 흐름

### 그룹 참여

카카오 로그인 → 그룹 생성 또는 초대 링크 참여 → 지도에 표시할 그룹 선택

그룹 생성자를 포함한 모든 구성원이 같은 참여 권한을 갖는다. 초대 링크로 참여할 때 별도의 가입 승인을 요구하지 않는다.

### 맛집 기록

맛집 추가 → 장소 검색 결과 선택 또는 네이버지도 공유 링크 가져오기 → 메달·추천 메뉴·가격·사진 입력 → 저장

메뉴는 개별 항목으로 추가한다. 장소 검색과 공유 링크 가져오기 과정에서 위치를 확인하고, 최종 저장은 사용자가 입력 내용을 검토한 뒤 수행한다.

### 맛집 탐색

지도 이동 또는 검색·메달 필터 → 목록·핀 선택 → 추천 메뉴·사진·평가 확인

목록은 현재 지도 중심에서 가까운 순으로 정렬한다. 여러 그룹의 기록을 함께 표시하며, 동일 장소의 그룹별 기록은 상세에서 구분한다.

### 의견 공유

식당 상세 → 댓글 또는 상승·유지·하락 의견 등록

등록자가 부여한 메달은 유지하면서 그룹원들의 의견 분포를 함께 보여준다.

## 5. 주요 기능과 정책

### 추천 내용이 남는 음식점 기록

음식점에 추천 메뉴와 메뉴별 가격, 사진, 배달 가능 앱을 함께 기록한다. 장소를 다시 찾았을 때 주문에 필요한 정보까지 확인하는 것을 목표로 한다.

### 초대 기반 그룹 공유

음식점과 사진은 가입한 그룹에서 열람한다. 구성원은 누구나 등록할 수 있고, 작성자는 자신이 등록한 음식점·메뉴·사진을 수정하거나 삭제한다. 닉네임과 그룹 이름도 수정할 수 있다.

### 메달과 평가 의견

추천 정도는 동메달·은메달·금메달로 표현한다. 메달은 등록자의 평가이며 작성자가 수정할 수 있다.

등록자를 제외한 그룹원은 상승·유지·하락 중 한 가지 의견을 선택하고 변경할 수 있다. 투표는 의견 수를 표시하며 메달을 자동 변경하지 않는다. 작성자가 메달을 변경하면 기존 표를 초기화해 변경된 평가에 대한 의견을 받는다.

### 지도 기반 탐색

현재 위치 표시, 검색, 메달 필터, 지도 중심 기준 거리순 목록을 제공한다. 가까운 핀은 확대 수준에 따라 묶어 식당 수를 표시하고, 누르면 확대하거나 선택 목록을 제공한다.

묶음 핀은 52px, 개별 메달 핀은 44px로 구분한다. 묶음에는 포함된 메달 색상을 반영하고 숫자를 표시한다.

### 그룹 탈퇴

탈퇴하면 해당 그룹에 등록한 본인의 음식점과 관련 기록을 삭제한다. 다른 그룹에 등록한 기록은 유지한다. 마지막 구성원이 탈퇴하면 그룹도 삭제한다.

## 6. 서비스 방향의 개선

### 초기 구조

위치인증 후 기존 메달 평가에 동의한 음식점이 3곳 이상이면 까탈리스트로 인정하고, 음식점 추천을 건의하면 관리자가 승인하는 구조를 설계했다.

### 재검토한 지점

지인들과 추천을 공유하려면 먼저 방문 조건을 충족하고 승인을 기다려야 했다. 또한 기존 평가에 동의하는 행동을 추천 자격과 연결하면서, 서로 다른 취향을 표현할 수 있는 범위를 좁힐 가능성이 있었다.

### 변경한 구조

모든 회원이 까탈리스트로 참여하고, 초대된 그룹 안에서 각자 음식점을 등록하도록 전환했다. 관리자의 심사 절차를 제거하고 작성자별 관리 권한을 적용했다.

메달 자동 조정도 검토했지만, 현재는 등록자의 평가와 그룹원의 의견을 구분해 표시한다. 서로 다른 취향이 원래의 추천 기록과 함께 남도록 구성했다.

### 변경의 의미

참여 조건을 줄이고 공동으로 기록할 수 있는 구조를 구현했다. 참여 빈도나 기록 증가에 미치는 효과는 실제 사용을 통해 확인할 예정이다.

## 7. 구현을 고려한 기술 선택

### React: 선언적 렌더링과 상태 관리

까탈로그는 그룹 선택·검색어·메달 필터·선택 식당 등 여러 UI 상태를 관리한다. Vanilla JavaScript 구현에서는 상태 변경과 DOM 갱신을 직접 연결해야 했고, 기능 확장에 따라 수동 동기화 로직의 유지보수 범위가 커졌다.

React의 **선언적 렌더링과 단방향 데이터 흐름**을 적용해, 상태를 props로 전달하고 JSX에서 UI를 도출하도록 구성했다. 상태 업데이트 시 React는 렌더 단계에서 다음 UI 트리를 계산하고, reconciliation을 거쳐 커밋 단계에서 필요한 DOM 변경을 반영한다. 이를 통해 명령형 DOM 갱신 로직을 줄이고 컴포넌트 단위로 책임을 분리했다.

네이버 지도 SDK는 **명령형 외부 시스템**으로 취급했다. 지도 인스턴스의 생성·해제와 이벤트 구독은 Effect의 setup·cleanup에 연결하고, 마커는 식별자를 기준으로 재사용하며 변경 사항을 증분 반영했다. 독의 고빈도 드래그 피드백은 refs와 직접 스타일 갱신으로 처리하고, 최종 선택값은 React state에 반영했다.

### GitHub Pages·Supabase: 정적 프론트엔드와 관리형 백엔드

React 애플리케이션은 Vite로 빌드하고 GitHub Pages에 배포한다. 인증·데이터베이스·사진 저장은 Supabase Auth·Postgres·Storage를 사용하며, 네이버 장소 검색은 Edge Function을 거친다.

그룹별 열람과 작성자별 수정 권한은 Postgres RLS로 검사한다. 사진은 비공개 버킷에 저장하고 접근 가능한 사용자에게 유효기간이 있는 서명 URL을 제공한다. 네이버 검색 API의 비밀 키는 서버 환경에서 관리한다.

현재 애플리케이션의 브라우저 중심 실행 구조에 필요한 서버 기능을 관리형 서비스와 함수로 구성했다.

### 검증과 배포

Node.js Test Runner로 데이터 변환·거리 정렬·장소 병합 등의 로직을 검사한다. Playwright의 Chromium·모바일 WebKit 환경에서 주요 사용자 흐름을 검증하고, DB 접근 정책은 별도 SQL 테스트로 확인한다.

GitHub Actions에서 테스트와 빌드를 수행한 뒤 배포한다. 자동화된 WebKit 테스트와 실제 iPhone에서의 동작 확인은 구분한다.

## 8. 현재 상태와 검증 과제

### 구현 완료

그룹 생성·초대, 맛집 공동 등록, 작성자 편집, 메뉴·가격·사진 기록, 지도 탐색, 댓글·평가 의견, 그룹별 접근 제어를 구현하고 배포했다.

### 후속 검증

- 초대받은 사용자가 첫 맛집을 등록하기까지 막히는 지점은 무엇인가?
- 메뉴와 가격 정보가 실제 방문 시 다시 조회되는가?
- 그룹 기록이 한 구성원에게 집중되거나 오래 갱신되지 않는가?
- 메달과 상승·유지·하락 의견의 의미가 명확하게 전달되는가?

성과 수치는 실제 사용 데이터를 확보한 뒤 제시한다.

## 9. 향후 확장: 공식 추천 지도

그룹별 추천이 축적되면 여러 그룹에서 독립적으로 추천한 음식점을 선별해 공식 추천 지도로 확장한다.

선별 기준은 등록 그룹 수, 고유 등록자 수, 메달 분포와 평가 의견을 함께 검토한다. 한 사람이 여러 그룹에 등록한 기록은 독립적인 추천 수와 구분한다.

공개 전에는 동일 음식점·지점 식별 기준, 그룹 기록의 공개 범위와 동의 절차, 선정·갱신 기준을 구체화해야 한다. 현재 그룹 공유 기능을 기반으로 데이터와 사용 경험을 축적하며 검토할 계획이다.
